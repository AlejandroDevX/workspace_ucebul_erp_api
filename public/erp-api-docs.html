Autenticación

El ERP no tiene login propio. Usa el token del Workspace como fuente de verdad. No se crean usuarios ni contraseñas en la base de datos del ERP.

El frontend envía el token de sesión del Workspace en cada solicitud al ERP:

Authorization: Bearer {workspace_token}

¿Qué hace el ERP con el token?

El middleware EnsureWorkspaceAuthenticated llama internamente al Workspace por cada solicitud:

GET {WORKSPACE_API_URL}/auth/me?application_slug=erp
Authorization: Bearer {workspace_token}

Si la respuesta es válida, se adjuntan a la request los datos del contexto del usuario:

{
  "workspace_user_id": 42,
  "workspace_user": { "id": 42, "name": "...", "email": "..." },
  "workspace_roles": [...],
  "current_application": { "slug": "erp", ... },
  "current_application_access": { ... },
  "current_application_permissions": {
    "contracts": {
      "module_name": "Contratos",
      "module_slug": "contracts",
      "permissions": [
        { "workspace_application_permission_slug": "erp.contracts.view" }
      ]
    }
  }
}

El workspace_user_id se asigna automáticamente en campos como erp_contract_created_by_workspace_user_id, erp_document_uploaded_by_workspace_user_id, etc. El frontend no necesita enviarlos en el payload.

Variables de entorno requeridas

WORKSPACE_API_URL=http://localhost:8000/api
WORKSPACE_APPLICATION_SLUG=erp

Permisos

La autenticación no es suficiente. Cada endpoint valida además que el usuario tenga la funcionalidad asignada en Workspace para la app erp.

El middleware EnsureWorkspacePermission recibe los permisos agrupados de Workspace y verifica que el slug requerido exista en la lista plana.

Estructura de permisos desde Workspace

{
  "contracts": {
    "module_name": "Contratos",
    "module_slug": "contracts",
    "permissions": [
      { "workspace_application_permission_slug": "erp.contracts.view" },
      { "workspace_application_permission_slug": "erp.contracts.create" }
    ]
  },
  "without_module": {
    "permissions": [
      { "workspace_application_permission_slug": "erp.workflows.view" }
    ]
  }
}

Uso en rutas (interno)

Route::get('/erp/contracts', ...)
    ->middleware([
        'workspace.auth',
        'workspace.permission:erp.contracts.view',
    ]);

Respuestas de error

CódigoCausaCuerpo de respuesta
401 Token ausente, inválido o expirado 
{ "success": false, "message": "Unauthenticated", "errors": [] }
403 (acceso) Usuario sin acceso a la app erp 
{ "success": false, "message": "You do not have access to this application", "errors": [] }
403 (permiso) Usuario sin el permiso requerido 
{
  "success": false,
  "message": "You do not have permission to perform this action",
  "errors": {
    "permission": ["Required permission: erp.contracts.create"]
  }
}
503 Workspace no responde o falla 
{ "success": false, "message": "Authentication service unavailable", "errors": [] }
